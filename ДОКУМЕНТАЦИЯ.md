## 1. Общее описание проекта

### 1.1 Что это за проект

**Charity AlmaU** — это веб-платформа, созданная для студентов университета AlmaU (Almaty Management University). Платформа позволяет студентам:

- **Отдавать вещи даром** — если вещь больше не нужна, её можно передать другому студенту бесплатно
- **Обмениваться вещами** — обменять свою вещь на нужную без денег
- **Сдавать вещи в аренду** — временно одолжить свою вещь за плату

Платформа доступна **только** для студентов AlmaU — вход осуществляется через корпоративный Microsoft-аккаунт (почта `@almau.edu.kz`). Это обеспечивает безопасность и доверие между участниками.

### 1.2 Для кого этот проект

- **Студенты AlmaU**, которые хотят избавиться от ненужных вещей
- **Первокурсники**, которые не хотят покупать всё новое (учебники, канцтовары, мебель)
- **Любые студенты**, которым нужно что-то временно (аренда проектора, спортинвентаря и т.д.)

### 1.3 Какие задачи решает

1. Экономия денег — получение вещей бесплатно или по низкой цене аренды
2. Экология — повторное использование вещей вместо выброса
3. Сообщество — создание культуры взаимопомощи внутри университета
4. Безопасность — все участники верифицированы через Microsoft-аккаунт AlmaU

### 1.4 Стек технологий

| Технология | Назначение |
|---|---|
| **Python 3.x** | Язык программирования серверной части |
| **Django 5.x** | Веб-фреймворк |
| **Django Channels** | WebSocket для чата в реальном времени |
| **SQLite / MySQL** | База данных (SQLite для разработки, MySQL для продакшена) |
| **django-allauth** | Авторизация через Microsoft OAuth |
| **WhiteNoise** | Раздача статических файлов |
| **HTML/CSS/JavaScript** | Фронтенд (без фреймворков, ванильный JS) |
| **Tailwind CSS (CDN)** | Утилитарные CSS-классы |
| **Inter (Google Fonts)** | Шрифт интерфейса |
| **VAPID / Web Push** | Push-уведомления в браузере |
| **ASGI (Daphne/Uvicorn)** | Сервер для WebSocket |
| **Docker** | Контейнеризация |
| **Nginx** | Реверс-прокси (продакшен) |

| Связь | Тип | Описание |
|---|---|---|
| User ↔ UserProfile | OneToOne | Каждый пользователь имеет ровно один профиль. Создаётся автоматически через signal `post_save` |
| User → Product | ForeignKey | Один пользователь может иметь много товаров |
| User → Favorite | ForeignKey | Один пользователь может иметь много избранных |
| Product → Favorite | ForeignKey | Один товар может быть в избранном у многих |
| Product → TradeRequest | ForeignKey | На один товар может быть много заявок |
| User → TradeRequest (requester) | ForeignKey | Один пользователь может отправить много заявок |
| User → TradeRequest (owner) | ForeignKey | Один пользователь может получить много заявок |
| Product → ProductImage | ForeignKey | У одного товара может быть до 4 дополнительных фото |

| User → RentItem (renter) | ForeignKey | Один пользователь может арендовать много товаров |
| User → RentItem (owner) | ForeignKey | Один пользователь может сдавать много товаров |

## 5. Подробное описание КАЖДОЙ функции (views.py)

### 5.1 `_notify_trade_request_async(product, requester, action)`

**Тип:** Вспомогательная функция (не view)
**Назначение:** Отправляет уведомление о новой заявке в фоновом потоке, чтобы не задерживать ответ пользователю.

**Пошагово:**
1. Определяет внутреннюю функцию `_run()`
2. Внутри `_run()` вызывает `notify_trade_request()` — отправку push-уведомления владельцу товара
3. Если произошла ошибка — логирует её, но не прерывает работу
4. Запускает `_run()` в отдельном `threading.Thread` с `daemon=True`
5. Не блокирует основной поток Django

### 5.2 `switch_language(request, lang_code)`

**URL:** `/lang/<str:lang_code>/`
**Метод:** GET
**Декораторы:** нет

**Что делает пошагово:**
1. Получает `next` URL из GET-параметра, или HTTP_REFERER, или `/`
2. Создаёт redirect-ответ на `next_url`
3. Проверяет, валиден ли `lang_code` через `check_for_language()`
4. Если валиден — устанавливает cookie `django_language` с этим языком (срок жизни 1 год)
5. Возвращает redirect

**Шаблон:** нет (redirect)
**Пример:** Пользователь нажимает "KK" в переключателе языков → браузер делает GET `/lang/kk/?next=/` → Django ставит cookie `django_language=kk` → redirect на `/` → страница на казахском.

### 5.3 `_get_favorite_ids(request)`

**Тип:** Вспомогательная функция (не view)
**Назначение:** Возвращает `set` из ID товаров, которые пользователь добавил в избранное.

**Пошагово:**
1. Проверяет, аутентифицирован ли пользователь
2. Если нет — возвращает пустой `set()`
3. Если да — делает запрос `Favorite.objects.filter(user=request.user).values_list('product_id', flat=True)`
4. Оборачивает в `set()` для быстрого поиска в шаблонах (`product.id in favorite_ids`)
5. Если таблица Favorite ещё не создана (OperationalError) — возвращает пустой `set()`

### 5.4 `login_view(request)`

**URL:** `/login/`
**Метод:** GET
**Декораторы:** нет
**Шаблон:** `login.html`

**Что делает:**
1. Просто рендерит страницу входа
2. На странице есть кнопка "Войти через Microsoft", которая ведёт на `{% provider_login_url 'microsoft' %}`

**Данные в шаблон:** нет (только стандартный `request`)

**Пример:** Пользователь открывает `/login/` → видит страницу с логотипом, описанием и кнопкой "Войти через Microsoft".

### 5.5 `logout_view(request)`

**URL:** `/logout/`
**Метод:** POST
**Декораторы:** нет

**Что делает пошагово:**
1. Проверяет, что метод запроса — POST
2. Если POST — вызывает `logout(request)` (очищает сессию)
3. Redirect на страницу логина
4. Если не POST — возвращает `HttpResponseBadRequest()` (код 400)

**Почему только POST:** Защита от случайного выхода через GET-запросы (например, через ссылку в email).

### 5.6 `onboarding_view(request)`

**URL:** `/onboarding/`
**Метод:** GET, POST
**Декораторы:** нет
**Шаблон:** `onboarding.html`

**Что делает пошагово:**
1. Проверяет GET-параметр `force` — если передан, показывает онбординг в любом случае
2. Если пользователь аутентифицирован, `force` не передан и в сессии `onboarded=True` — redirect на главную
3. Если POST — записывает `session['onboarded'] = True` и redirect на главную
4. Если GET — рендерит страницу онбординга ("О проекте")

**Данные в шаблон:** нет (контент статический, с поддержкой трёх языков)

### 5.7 `home_view(request)`

**URL:** `/` (корень сайта)
**Метод:** GET
**Декораторы:** нет
**Шаблон:** `home.html`

**Что делает пошагово:**
1. Получает GET-параметр `category` и преобразует в `int` (или None)
2. Получает GET-параметр `type` — валидирует, что это `free`, `exchange`, `rental` или `all`
3. Получает GET-параметр `q` — строку поиска
4. Формирует QuerySet: `Product.objects.filter(is_approved=True).order_by('-created_at')`
5. Если пользователь аутентифицирован — исключает его собственные товары
6. Если выбран тип — фильтрует по `type`
7. Если выбрана категория — фильтрует по `main_category`, `subcategory` или `sub_subcategory`

### 5.11 `requests_view(request)`

**URL:** `/requests/`
**Метод:** GET, POST
**Декораторы:** `@login_required`
**Шаблон:** `requests.html`

**POST-обработка (AJAX):**

Получает `req_id` и `decision`, затем:

- `accept` (владелец подтверждает): `status → accepted`
- `reject` (владелец отклоняет): `status → rejected`
- `cancel` (запросивший отменяет): `status → cancelled`
- `handover` (владелец отдал вещь):
  - Для `take`/`exchange`: `status → completed`
  - Для `rent`: `status → in_progress`, обновление `RentItem`
- `mark_returned` (владелец завершает аренду):
  - `status → completed`, `RentItem.status → returned`

Если AJAX — возвращает `{'ok': True, 'status': new_status, 'action': action}`.
Если обычный — redirect на `/requests/`.

**GET-запрос:**
1. Получает входящие заявки (я владелец) со статусами pending/accepted/in_progress
2. Получает исходящие заявки (я запросил)
3. Подгружает RentItem для аренд
4. Получает историю (completed/rejected/cancelled, до 50 шт.)
5. Отключает кэш (`Cache-Control: no-store`)

**Данные в шаблон:**
```python
{
    'incoming': list[TradeRequest],
    'outgoing': list[TradeRequest],
    'history': list[TradeRequest],
}
```

## 7. Описание WebSocket (consumers.py)

### 7.1 Общая архитектура

Чат использует **Django Channels** для обмена сообщениями в реальном времени через WebSocket.

**Путь WebSocket:** `ws[s]://<host>/ws/chat/<chat_id>/`

**Channel Layer:** `InMemoryChannelLayer` (для продакшена следует заменить на Redis).

### 7.2 ChatConsumer — подробное описание

```python
class ChatConsumer(AsyncWebsocketConsumer):
```

Наследуется от `AsyncWebsocketConsumer` — асинхронный обработчик WebSocket.

#### Метод `connect(self)`

**Когда вызывается:** Когда клиент (JavaScript) открывает WebSocket-соединение.

**Пошагово:**
1. Извлекает `chat_id` из URL: `self.scope['url_route']['kwargs']['chat_id']`
2. Формирует имя группы: `f'chat_{self.chat_id}'` (например, `chat_42`)
3. Получает пользователя из scope
4. Если пользователь не аутентифицирован → `self.close()` (закрывает соединение)
5. Проверяет, является ли пользователь участником чата через `_is_participant`
6. Если не участник → `self.close()`
7. Добавляет соединение в группу: `channel_layer.group_add(group_name, channel_name)`
8. Принимает соединение: `self.accept()`

#### Метод `disconnect(self, close_code)`

**Когда вызывается:** Когда клиент закрывает соединение (уход со страницы, потеря сети).

**Что делает:**
1. Удаляет соединение из группы: `channel_layer.group_discard(group_name, channel_name)`

#### Метод `receive(self, text_data=None, bytes_data=None)`

**Когда вызывается:** Когда клиент отправляет сообщение через WebSocket.

**Пошагово:**
1. Если `text_data` пусто — ничего не делает
2. Парсит JSON: `json.loads(text_data)`
3. Извлекает текст: `data.get('text', '').strip()`
4. Если текст пустой — ничего не делает
5. Получает пользователя из scope
6. Создаёт сообщение в БД через `_create_message`
7. Отправляет email-уведомление через `_async_notify`
8. Формирует payload:
   ```python
   {
       'type': 'chat.message',
       'id': message.id,
       'sender': user.username,
       'sender_id': user.id,
       'text': message.text,
       'status': 'sent',
       'is_read': False,
       'created_at': '2026-04-29T12:00:00',
       'is_own': True,
   }
   ```
9. Рассылает в группу: `channel_layer.group_send(group_name, {...})`

#### Метод `chat_message(self, event)`

**Когда вызывается:** Когда `group_send` доставляет сообщение всем участникам группы.

**Пошагово:**
1. Получает message из event
2. Если отправитель — не текущий пользователь → `is_own = False`
3. Отправляет JSON клиенту через WebSocket: `self.send(text_data=json.dumps(message))`

#### Метод `_is_participant(self, user_id, chat_id)` (sync→async)

**Что делает:**
1. Находит Chat по id
2. Проверяет, что user_id есть среди участников
3. Возвращает `True`/`False`

#### Метод `_create_message(self, user_id, chat_id, text)` (sync→async)

**Что делает:**
1. Находит User и Chat
2. Создаёт `Message.objects.create(chat=chat, sender=user, text=text)`
3. Возвращает созданный объект Message

### 7.3 Вспомогательная функция `_async_notify`

```python
@database_sync_to_async
def _async_notify(chat_id, sender_id, text):
```

**Что делает:**
1. Находит Chat и User по id
2. Вызывает `notify_new_message(chat, sender, text)` — отправляет email через Microsoft Graph API
3. При ошибке — молча игнорирует (pass)

### 7.4 Жизненный цикл сообщения через WebSocket

```
Пользователь A набирает текст и нажимает Enter
    │
    ▼
JavaScript:  socket.send(JSON.stringify({ text: "Привет!" }))
    │
    ▼ (WebSocket)
ChatConsumer.receive()
    │
    ├── _create_message()  → Message в БД
    ├── _async_notify()    → email владельцу
    └── group_send()       → всем в группе 'chat_42'
              │
              ├── Пользователь A → ChatConsumer.chat_message() → is_own=True
              │       → socket.onmessage → отображает сообщение справа
              │
              └── Пользователь B → ChatConsumer.chat_message() → is_own=False
                      → socket.onmessage → отображает сообщение слева
```

### 9.4 Частые вопросы на код-ревью и ответы

**В: Почему авторизация только через Microsoft?**
О: Проект предназначен только для студентов AlmaU. Вход через корпоративный Microsoft-аккаунт с почтой `@almau.edu.kz` обеспечивает верификацию пользователей. Ограничение реализовано через `ACCOUNT_ADAPTER` и `SOCIALACCOUNT_ADAPTER` в `settings.py`, которые ссылаются на `core/adapters.py`.

**В: Почему поиск по товарам происходит в Python, а не в SQL?**
О: Поиск выполняется в Python (`q_lower in title.lower()`) для корректной работы с кириллицей и казахскими символами на любой СУБД (SQLite не поддерживает `icontains` для юникода). Это допустимо при текущих объёмах данных.

**В: Как работает модерация товаров?**
О: Каждый новый товар создаётся с `is_approved=False`. Администратор одобряет его через Django Admin (`/admin/`), устанавливая `is_approved=True`. В каталоге отображаются только одобренные товары.

**В: Почему WebSocket использует InMemoryChannelLayer?**
О: Для разработки и MVP это достаточно. В продакшене с несколькими воркерами нужно заменить на `channels_redis.core.RedisChannelLayer`.

**В: Как обеспечивается безопасность WebSocket?**
О: В методе `connect()` проверяется:
1. Аутентификация пользователя (`user.is_anonymous`)
2. Членство в чате (`_is_participant`)
Если проверки не пройдены — соединение закрывается.

**В: Что происходит с товаром после принятия заявки?**
О: `product.status` меняется на `taken` или `exchanged` при создании заявки. Однако товар не скрывается из каталога — он по-прежнему видим, но может быть недоступен для повторного отклика.

**В: Как работают push-уведомления?**
О: Используется VAPID (Voluntary Application Server Identification). Публичный ключ передаётся на фронтенд через context processor `vapid_key`. Скрипт `push.js` подписывает браузер и сохраняет подписку через POST `/chat/push/subscribe/`. При новых заявках или сообщениях сервер отправляет push через `pywebpush`.

**В: Как работает тёмная тема?**
О: Двойной механизм:
1. `localStorage.dark_mode` — для мгновенного применения при загрузке страницы (до рендера)
2. `UserProfile.dark_mode` — для синхронизации между устройствами
При toggle: AJAX-запрос обновляет профиль, JavaScript обновляет localStorage и класс body.

**В: Почему для уведомлений о заявках используется threading, а для email в чате — database_sync_to_async?**
О: В views.py (синхронный код) удобнее использовать `threading.Thread`. В consumers.py (асинхронный код Channels) нужен `database_sync_to_async` для доступа к БД из async-контекста.

## 10. Инструкция по запуску для чайника

### 10.1 Что нужно установить заранее

1. **Python 3.10+** — скачать с https://python.org
   - При установке на Windows обязательно отметить "Add Python to PATH"

2. **Git** — скачать с https://git-scm.com (если проект клонируется из репозитория)

### 10.2 Пошаговая инструкция

#### Шаг 1: Скачать проект

```bash
# Если проект в Git-репозитории:
git clone <URL_РЕПОЗИТОРИЯ>
cd CharityAlmauWeb

# Если проект в архиве — распаковать и перейти в папку
```

#### Шаг 2: Создать виртуальное окружение

```bash
# macOS / Linux:
python3 -m venv venv
source venv/bin/activate

# Windows:
python -m venv venv
venv\Scripts\activate
```

После активации в терминале должно появиться `(venv)` перед строкой.

#### Шаг 3: Установить зависимости

```bash
pip install -r requirements.txt
```

Это установит Django, Channels, allauth и все остальные пакеты.

#### Шаг 4: Создать файл `.env`

Создайте файл `.env` в корне проекта (рядом с `manage.py`):

```env
DEBUG=true
SECRET_KEY=your-secret-key-at-least-50-characters-long-replace-this
USE_SQLITE=true
ALLOWED_HOSTS=localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS=http://localhost:8000,http://127.0.0.1:8000

# Microsoft OAuth (получить на portal.azure.com)
MS_CLIENT_ID=your-client-id
MS_CLIENT_SECRET=your-client-secret
MS_TENANT=your-tenant-id

# Push уведомления (опционально)
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
```

#### Шаг 5: Применить миграции (создать таблицы в БД)

```bash
python manage.py migrate
```

Эта команда создаст файл `db.sqlite3` и все таблицы в нём.

#### Шаг 6: Создать суперпользователя (администратора)

```bash
python manage.py createsuperuser
```

Программа спросит:
- Username: введите любое (например, `admin`)
- Email: введите email (например, `admin@almau.edu.kz`)
- Password: введите пароль (дважды)

#### Шаг 7: Загрузить категории (опционально)

```bash
python manage.py shell -c "exec(open('core/populate_categories.py').read())"
```

Или создайте категории через админку.

#### Шаг 8: Собрать статику

```bash
python manage.py collectstatic --no-input
```

#### Шаг 9: Запустить сервер

```bash
# Обычный HTTP-сервер (без WebSocket):
python manage.py runserver

# Для WebSocket чата нужен ASGI-сервер:
daphne -b 127.0.0.1 -p 8000 CharityAlmaWeb.asgi:application
# или
uvicorn CharityAlmaWeb.asgi:application --host 127.0.0.1 --port 8000
```

#### Шаг 10: Открыть в браузере

- Сайт: http://127.0.0.1:8000/
- Админка: http://127.0.0.1:8000/admin/

### 10.3 Как зайти в админку

1. Откройте http://127.0.0.1:8000/admin/
2. Введите username и password суперпользователя (из шага 6)
3. В админке можно:
   - Одобрять товары (Products → выбрать → `is_approved = True`)
   - Управлять пользователями
   - Создавать категории
   - Просматривать заявки и чаты

### 10.4 Как одобрить товар (модерация)

1. Зайти в админку: http://127.0.0.1:8000/admin/
2. Перейти в "Products" (или "Продукты")
3. Найти товар со статусом `is_approved = False`
4. Поставить галочку "Одобрено модератором"
5. Нажать "Сохранить"
6. Товар появится в каталоге для всех пользователей

```bash
# Сборка и запуск:
docker-compose up --build
```

### 10.6 Частые проблемы

| Проблема | Решение |
|---|---|
| `SECRET_KEY must be set via environment` | Создайте файл `.env` с `SECRET_KEY=...` |
| `No module named 'allauth'` | Запустите `pip install -r requirements.txt` |
| `OperationalError: no such table` | Запустите `python manage.py migrate` |
| Товар не отображается в каталоге | Проверьте `is_approved=True` в админке |
| WebSocket не подключается | Используйте `daphne` или `uvicorn` вместо `runserver` |
| Не работает вход через Microsoft | Проверьте `MS_CLIENT_ID`, `MS_CLIENT_SECRET`, `MS_TENANT` в `.env` |
| Нет категорий в форме добавления | Создайте категории через админку или загрузите через скрипт |
