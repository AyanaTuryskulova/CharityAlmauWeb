# USER FLOWS: как работает функционал

Этот документ объясняет ключевые сценарии сайта на уровне:
- что нажимает пользователь;
- какой view/код срабатывает;
- что читается/записывается в БД;
- что возвращает сервер;
- что видит пользователь в итоге.

---

## 1) Добавить/убрать из избранного

### Действия пользователя
- Пользователь нажимает на сердечко в карточке товара.

### Что делает код
- Форма `like-form` в шаблонах отправляется через AJAX (JS в `core/templates/base.html`).
- Запрос идет в `favorite_toggle(request, product_id)` из `core/views.py`.

### Что происходит в БД
- Проверяется, не свой ли это товар.
- Если записи в `Favorite` нет -> создается (`Favorite.objects.get_or_create`).
- Если запись есть -> удаляется.

### Что возвращает сервер
- Для AJAX: JSON вида `{ ok: true, is_favorite: true/false }`.
- Для обычного запроса: `redirect` на `next`/текущую страницу.

### Что видит пользователь
- Сердце переключается между `♡` и `♥` без перезагрузки страницы.

---

## 2) Открыть карточку товара

### Действия пользователя
- Клик по карточке в ленте.

### Что делает код
- Вызывается `product_detail(request, product_id)`.
- Формируется галерея: главное фото + дополнительные (`ProductImage`).
- Проверяется, можно ли показывать не одобренный товар.

### Что происходит в БД
- Чтение `Product`, `Favorite`, `TradeRequest`, `ProductImage`.

### Что возвращает сервер
- HTML страницы `core/templates/product_detail.html`.

### Что видит пользователь
- Детальную карточку, галерею фото, кнопки отклика/чата.

---

## 3) Откликнуться на товар (заявка)

### Действия пользователя
- Нажимает кнопку `Откликнуться`.

### Что делает код
- Вызывается `product_action(request, product_id, action)`.
- Создается объект `TradeRequest`.
- Статус товара обновляется (`taken`/`exchanged`).
- Уведомление отправляется асинхронно через `_notify_trade_request_async`.

### Что происходит в БД
- `TradeRequest.objects.create(...)`.
- `Product.status` меняется и сохраняется.

### Что возвращает сервер
- `redirect` на `next` (часто на страницу заявок).

### Что видит пользователь
- Переход на нужную страницу, заявка появляется в списке.

---

## 4) Мои заявки (входящие/исходящие)

### Действия пользователя
- Открывает страницу `Заявки`.
- Подтверждает/отклоняет/отменяет/завершает заявку.

### Что делает код
- `requests_view(request)`:
  - GET: собирает входящие и исходящие заявки;
  - POST: меняет статус заявки в зависимости от действия.

### Что происходит в БД
- Чтение/обновление `TradeRequest`.
- Для аренды дополнительно обновляется `RentItem`.

### Что возвращает сервер
- GET: HTML `requests.html`.
- POST: `redirect` обратно на `requests`.

---

## 5) Создание объявления

### Действия пользователя
- Открывает форму `Добавить`, заполняет поля, прикладывает фото, публикует.

### Что делает код
- `add_product(request)` валидирует данные через `ProductForm`.
- Нормализует цену.
- Проверяет, что есть минимум 1 фото.
- Создает `Product` и до 4 записей `ProductImage`.
- При необходимости делает автоподсказку по фото (`infer_product_from_image`).

### Что происходит в БД
- Вставка `Product`.
- Вставка `ProductImage` (дополнительные фото).

### Что возвращает сервер
- При успехе: `redirect('my_ads')`.
- При ошибке: HTML формы с ошибками.

---

## 6) Редактирование объявления

### Действия пользователя
- В профиле нажимает `Редактировать`.

### Что делает код
- `edit_product(request, product_id)`:
  - проверяет, что объявление принадлежит текущему пользователю;
  - применяет `ProductForm`;
  - обновляет фото `images_0..images_4`;
  - очищает поля, неактуальные для выбранного типа (`free/rental/exchange`).

### Что происходит в БД
- Обновление `Product`.
- Обновление/создание `ProductImage`.

### Что возвращает сервер
- При успехе: `redirect('my_ads')`.
- При ошибке: HTML формы редактирования.

---

## 7) Профиль: мои объявления и избранное

### Действия пользователя
- Открывает профиль.
- Удаляет объявление или убирает товар из избранного.

### Что делает код
- `my_ads(request)`:
  - GET: отдает объявления и избранное;
  - POST: удаляет объявление или запись `Favorite`.
- Удаление из избранного в профиле выполняется через AJAX.

### Что происходит в БД
- Чтение `Product` и `Favorite`.
- Удаление `Product`/`Favorite` по действию.

### Что возвращает сервер
- GET: HTML `my_ads.html`.
- AJAX POST: JSON с `ok` и обновленным количеством избранного.
- Обычный POST: `redirect('my_ads')`.

---

## 8) Чаты: список, отправка, непрочитанные

### Действия пользователя
- Открывает чаты, выбирает диалог, отправляет сообщение.

### Что делает код
- `chat_list(request, chat_id)`:
  - собирает чаты;
  - считает непрочитанные только от других пользователей;
  - отмечает входящие как прочитанные для открытого чата.
- `send_message(request, chat_id)` создает сообщение.
- `get_messages(request, chat_id)` отдает JSON списка сообщений.

### Что происходит в БД
- Чтение `Chat`, `Message`.
- Вставка `Message`.
- Обновление `Message.is_read`.

### Что возвращает сервер
- `chat_list` -> HTML.
- `send_message` -> redirect.
- `get_messages` -> JSON.

---

## 9) Запуск/поиск чата

### Действия пользователя
- Нажимает `Написать` в карточке товара.

### Что делает код
- `start_chat(request, user_id)`:
  - ищет уже существующий чат (с учетом товара, если передан `product_id`);
  - если нет, создает новый `Chat` и участников.

### Что происходит в БД
- Чтение/вставка `Chat`.
- Записи в связующей таблице участников.

### Что возвращает сервер
- `redirect` на `chat_list` с `chat_id`.

---

## 10) Аренда: список, создание, обновление

### Действия пользователя
- Открывает раздел аренды, отправляет заявку на аренду, меняет статусы.

### Что делает код
- `rentals_list(request)` отдает доступные для аренды товары.
- `create_rental(request)` создает/переиспользует заявку + создает `RentItem`.
- `update_rental(request, rental_id)` обновляет статус аренды.

### Что происходит в БД
- Чтение `Product`, `RentItem`, `TradeRequest`.
- Вставка/обновление `RentItem`, `TradeRequest`, `Product.status`.

### Что возвращает сервер
- HTML или JSON (если запрошен API-формат).

---

## 11) Смена языка

### Действия пользователя
- Меняет язык в меню сайта или в Django Admin.

### Что делает код
- `switch_language(request, lang_code)` ставит cookie языка.
- В Admin используется стандартный `i18n/setlang/` через форму в `admin/base_site.html`.

### Что происходит в БД
- БД не меняется, используется cookie + locale-файлы.

### Что возвращает сервер
- `redirect` на предыдущую страницу.

---

## 12) Push-подписки браузера

### Действия пользователя
- Разрешает/отключает web push.

### Что делает код
- `push_subscribe(request)` сохраняет endpoint и ключи.
- `push_unsubscribe(request)` удаляет endpoint.

### Что происходит в БД
- Вставка/обновление/удаление `PushSubscription`.

### Что возвращает сервер
- JSON `{ ok: true/false }`.

## Заметки по коду (где что и как устроено)

### 1) Основная backend-логика
- Файл: `core/views.py`.
- Здесь находятся почти все пользовательские сценарии: главная, карточки, профиль, заявки, чат, аренда, избранное.
- В этом же файле есть служебные helper-функции (например, `_get_favorite_ids`, `_notify_trade_request_async`).

### 2) Модели и БД
- Файл: `core/models.py`.
- Основные таблицы:
  - `Product` — объявления;
  - `ProductImage` — дополнительные фото объявления;
  - `Favorite` — избранное;
  - `TradeRequest` — заявки по объявлениям;
  - `Chat`, `Message` — чаты и сообщения;
  - `RentItem` — аренды;
  - `PushSubscription` — web push подписки;
  - `Category` — категории.

### 3) Формы и валидация
- Файл: `core/forms.py`.
- `ProductForm` управляет валидацией полей объявления и queryset категорий.
- Часть валидации и нормализации также делается прямо в `views.py` (например, цена, обязательность фото).

### 4) Шаблоны и UI
- Базовый шаблон: `core/templates/base.html`.
- Навбар: `core/templates/includes/navbar.html`.
- Ключевые страницы:
  - `core/templates/home.html` — каталог;
  - `core/templates/product_detail.html` — карточка товара;
  - `core/templates/add_product.html` и `core/templates/edit_product.html` — создание/редактирование;
  - `core/templates/my_ads.html` — профиль;
  - `core/templates/chat/index.html` — чаты.

### 5) JS-поведение (встроенное в шаблоны)
- Избранное через AJAX обрабатывается в `base.html` (делегированный submit для `like-form`).
- Часть поведения страниц (табы, превью фото, фильтры, модалки) реализована локальными скриптами внутри соответствующих шаблонов.
- Чат использует и HTTP, и WebSocket (см. JS в `chat/index.html` + серверную часть channels).

### 6) Локализация (RU/KK/EN)
- Переводы: `locale/kk/LC_MESSAGES/django.po`, `locale/en/LC_MESSAGES/django.po`.
- Компиляция в `.mo` выполняется скриптом `compile_locale.py`.
- Для динамических/БД категорий используется фильтр `tr_category` из `core/templatetags/category_i18n.py`.

### 7) Сигналы, уведомления и внешние сервисы
- Email/push уведомления: `core/notifications.py`, `core/email_utils.py`, `core/static/js/push.js`.
- Асинхронность в некоторых местах реализована через `threading` (например отправка уведомления по заявке).

### 8) Важные практические замечания
- Если что-то «не переводится», обычно проблема в:
  1) строка не завернута в `{% trans %}` / `gettext`,
  2) нет `msgid/msgstr` в `.po`,
  3) не скомпилированы локали.
- Если UI «прыгает»/перезагружается, проверять:
  - JS-обработчик submit,
  - fallback `form.submit()` в `catch`,
  - есть ли `X-Requested-With` и `ajax=1`.

## Карта корня проекта (что где в корне)

Ниже кратко описано назначение основных папок и файлов в корне проекта.

### Папки
- `CharityAlmaWeb/` — Django project config:
  - `settings.py`, `urls.py`, `asgi.py`, `wsgi.py`.
- `core/` — основное приложение проекта (модели, views, шаблоны, статика, templatetags, миграции).
- `docs/` — документация по архитектуре, API и пользовательским потокам.
- `locale/` — переводы (`.po/.mo`) для языков.
- `media/` — загружаемые пользователями файлы (фото и т.д.).
- `.venv/` — локальное виртуальное окружение Python.
- `.vscode/` — локальные настройки редактора.

### Ключевые файлы
- `manage.py` — запуск команд Django.
- `requirements.txt` — зависимости Python.
- `.env` — переменные окружения (секреты, DB, OAuth, push).
- `compile_locale.py` — компиляция переводов `.po -> .mo`.
- `README.md` — быстрый старт и общая информация по проекту.
- `docker-compose.yml`, `Dockerfile` — контейнерный запуск.
- `db.sqlite3` — локальная SQLite БД (если включен sqlite-режим).

### Быстрый маршрут по коду (для новых задач)
- Нужен новый пользовательский сценарий -> `core/views.py` + шаблон в `core/templates/...`.
- Нужны новые поля/сущности -> `core/models.py` + миграции.
- Нужна валидация формы объявления -> `core/forms.py`.
- Нужен перевод -> `locale/*/LC_MESSAGES/django.po` + компиляция.
- Нужен UI-фикс -> чаще всего `core/templates/base.html` или конкретный шаблон страницы.
